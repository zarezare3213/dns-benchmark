# ابزار سنجش سرعت و پایداری DNSهای عمومی

## ۱. معماری کلی

```
dns-benchmark/
├── main.py                # نقطهٔ ورود برنامه
├── dns_providers.json     # فهرست دستچین‌شدهٔ سرویس‌دهنده‌های DNS معتبر
├── requirements.txt
├── core/
│   ├── resolver.py        # اجرای یک پرس‌وجوی DNS و اندازه‌گیری زمان/خطا
│   ├── benchmark.py       # اجرای موازی تست‌ها روی همهٔ سرورها + آمارگیری
│   └── updater.py         # بارگذاری/ادغام/ویرایش فهرست سرویس‌دهنده‌ها
└── gui/
    └── app.py             # رابط گرافیکی Tkinter (جدول، فیلتر، جست‌وجو، مرتب‌سازی)
```

جریان کار: `main.py` فهرست JSON را می‌خواند → `gui/app.py` آن را در جدول
نشان می‌دهد → با کلیک روی «اجرای تست»، `core/benchmark.py` به‌صورت موازی
(چند ریسمانی) برای هر سرور DNS، چند دامنهٔ آزمایشی را چند بار پرس‌وجو
می‌کند (با `core/resolver.py`) و آمار را محاسبه می‌کند → نتیجه در جدول
به‌روزرسانی می‌شود.

## ۲. کتابخانه‌های استفاده‌شده

- **dnspython** — برای ارسال پرس‌وجوی DNS مستقیم به یک IP مشخص (بدون
  دخالت در تنظیمات DNS سیستم).
- **tkinter** — رابط گرافیکی (بخشی از خود پایتون است، نیازی به نصب جدا ندارد).
- **concurrent.futures** — اجرای موازی تست‌ها برای سرعت بیشتر.
- **PyInstaller** — تبدیل پروژه به یک فایل EXE مستقل برای ویندوز.

## ۳. روش تست و معیارها

برای هر سرور DNS:
1. به تعداد دامنه‌های آزمایشی (پیش‌فرض: `example.com`, `google.com`,
   `cloudflare.com`, `wikipedia.org` — قابل تغییر از داخل برنامه) و به
   تعداد `repeats` بار (پیش‌فرض ۳ بار) پرس‌وجوی نوع A ارسال می‌شود.
2. زمان هر پاسخ موفق با `time.perf_counter()` ثبت می‌شود.
3. از مجموع نتایج:
   - **میانگین زمان پاسخ (ms)**
   - **جیتر** = انحراف‌معیار زمان‌ها (شاخص پایداری؛ عدد کوچک‌تر = پایدارتر)
   - **درصد موفقیت** = پرس‌وجوهای موفق ÷ کل پرس‌وجوها
   - **وضعیت نهایی**: قطع (۰٪ موفقیت) / ضعیف (کمتر از ۷۰٪ موفقیت) /
     کند (میانگین بیش از ۳۰۰ میلی‌ثانیه) / پایدار

نتایج بر اساس درصد موفقیت (نزولی) و سپس میانگین زمان (صعودی) رتبه‌بندی
می‌شوند.

## ۴. دربارهٔ «کدام سایت‌ها یا برنامه‌ها با هر DNS قابل‌دسترس‌اند؟»

**این کار با تست DNS به‌تنهایی به‌طور کامل ممکن نیست**، به این دلایل:

- موفقیت resolve شدن یک دامنه فقط یعنی سرور DNS آدرس IP آن را برگردانده؛
  تضمینی نیست که بعداً بتوان به آن IP وصل شد (فایروال، مسدودسازی در سطح
  IP/SNI، محدودیت جغرافیایی CDN، یا مسدودسازی در سطح اپلیکیشن می‌توانند
  جدا از DNS عمل کنند).
- برخی DNSهای فیلترکننده (مثل CleanBrowsing) عمداً برخی دامنه‌ها را
  resolve نمی‌کنند؛ این با «قطع بودن سرور DNS» فرق دارد.
- «تمام برنامه‌ها»یی که کاربر ممکن است استفاده کند، از پیش قابل پیش‌بینی
  نیست؛ هر برنامه دامنه‌های خاص خودش را دارد.

**راهکار درست و قانونی** (که این پروژه امکان افزودنش را دارد ولی به‌صورت
پیش‌فرض فعال نیست، چون فراتر از «سنجش DNS» است): برای فهرستی از دامنه‌های
مشخص که *خود کاربر* تعیین می‌کند، دو لایهٔ تست انجام شود:
1. **تست DNS** (همین برنامه) → آیا دامنه resolve می‌شود؟
2. **تست دسترسی لایهٔ کاربرد** روی IP برگشتی: یک اتصال TCP به پورت ۴۴۳
   (یا یک درخواست HTTP HEAD) برای بررسی اینکه آیا واقعاً می‌توان به آن
   سرویس وصل شد. تابع کمکی `core.resolver.check_tcp_reachability` نقطهٔ
   شروع خوبی برای این کار است.

این روش، بررسی «دسترسی‌پذیری چند دامنهٔ مشخص» را ممکن می‌کند، نه ادعای
«همهٔ سایت‌ها/برنامه‌های قابل‌دسترس با این DNS» — چون چنین ادعایی از نظر
فنی قابل اثبات کامل نیست.

## ۵. به‌روزرسانی فهرست DNSها

فایل `dns_providers.json` یک فهرست دستچین‌شده از سرویس‌دهنده‌های شناخته‌شده
است (نه «همهٔ DNSهای دنیا»). دو راه برای به‌روزرسانی:
- ویرایش مستقیم فایل JSON (افزودن/حذف/اصلاح آدرس‌ها).
- استفاده از `core.updater.merge_provider_lists` برای ادغام یک فایل
  JSON دیگر (با همان ساختار) با فهرست فعلی — مثلاً وقتی کاربر خودش از
  سایت رسمی یک سرویس‌دهندهٔ جدید آدرس‌ها را جمع کرد.

هیچ کشف خودکار DNS از اینترنت انجام نمی‌شود؛ این تصمیم آگاهانه است تا
برنامه هرگز «تمام DNSهای موجود را یافتم» ادعا نکند.

```bash
python -m venv venv
venv\Scripts\activate          # ویندوز
pip install -r requirements.txt
python main.py
```

## ۷. تبدیل به فایل EXE (ویندوز ۱۰ و ۱۱)

> **نکتهٔ مهم:** PyInstaller نمی‌تواند cross-compile کند — یعنی فایل
> `.exe` واقعی فقط وقتی ساخته می‌شود که خودِ PyInstaller روی یک سیستم
> ویندوزی اجرا شود. اجرای آن روی لینوکس یک فایل اجرایی لینوکسی (ELF)
> می‌سازد، نه `.exe`. بنابراین دو راه واقعی برای گرفتن EXE وجود دارد:

### روش الف) خودکار با GitHub Actions (بدون نیاز به داشتن ویندوز)
در پوشهٔ پروژه فایل `.github/workflows/build-exe.yml` قرار دارد که یک
ماشین واقعی ویندوز را در GitHub اجرا می‌کند، پروژه را می‌سازد و EXE
نهایی را به‌عنوان artifact قابل‌دانلود آماده می‌کند:

1. این پوشه را در یک ریپازیتوری گیت‌هاب (خصوصی یا عمومی) push کنید.
2. به تب **Actions** ریپازیتوری بروید؛ workflow با نام «Build Windows EXE»
   به‌طور خودکار اجرا می‌شود (یا دستی از همان تب با «Run workflow» اجرایش کنید).
3. پس از پایان (چند دقیقه)، از بخش **Artifacts** همان اجرا، فایل
   `DNSBenchmark-windows-exe` را دانلود کنید — داخلش `DNSBenchmark.exe`
   واقعی و اجراشدنی روی ویندوز ۱۰/۱۱ است.

### روش ب) دستی، روی یک سیستم ویندوزی
```bash
pip install -r requirements.txt
pyinstaller --onefile --windowed --name DNSBenchmark ^
    --add-data "dns_providers.json;." ^
    main.py
```

در هر دو روش، توضیح گزینه‌ها یکسان است:
- `--onefile` → یک فایل EXE واحد تولید می‌شود.
- `--windowed` → بدون باز شدن پنجرهٔ کنسول سیاه (چون برنامه GUI دارد).
- `--add-data "dns_providers.json;."` → فایل JSON فهرست DNSها همراه EXE
  بسته‌بندی می‌شود (در ویندوز جداکننده `;` است؛ در لینوکس/مک `:`).

خروجی نهایی در پوشهٔ `dist/DNSBenchmark.exe` قرار می‌گیرد. این فایل را
می‌توان مستقل، بدون نیاز به نصب پایتون روی سیستم مقصد، اجرا کرد.

> نکته: اگر آنتی‌ویروس ویندوز فایل EXE تازه‌ساخته‌شده را به‌اشتباه مشکوک
> تشخیص داد (رفتار شناخته‌شده و رایج برای فایل‌های PyInstaller
> امضا‌نشده)، می‌توانید فایل را با یک گواهی امضای کد (code signing
> certificate) امضا کنید یا آن را به Windows Defender اضافه به‌عنوان
> استثنا معرفی کنید.

## ۸. محدودیت و اصول رعایت‌شده در طراحی

- برنامه هرگز تنظیمات DNS سیستم را بدون تأیید صریح کاربر (کلیک + پنجرهٔ
  تأیید) تغییر نمی‌دهد و این کار را با `netsh` فقط روی آداپتوری که کاربر
  نامش را وارد کرده انجام می‌دهد.
- هیچ ادعایی مبنی بر یافتن «تمام DNSهای موجود در دنیا» ندارد؛ فهرست
  همیشه یک زیرمجموعهٔ قابل‌ویرایش و قابل‌گسترش است.
- تست «دسترسی به سایت/برنامه» به‌صراحت به‌عنوان چیزی جدا از تست DNS و با
  محدودیت‌هایش توضیح داده شده، نه ادعای غیرواقعی.
